请在当前文件夹中从零实现一个可以在浏览器中运行的“实时协作白板与离线冲突合并系统”。它不是普通画板，而是一个支持多客户端实时同步、断网离线编辑、重连合并、每用户撤销重做、服务端持久化和冲突可解释的交互工具。请在首轮内独立完成全部工作，不要向我提问或请求确认，也不要等待我输入；遇到不确定的地方按最合理的工程方案自行决定，并在 README 中说明关键取舍。

1. 项目启动
- 在当前文件夹中完成项目，不要新建嵌套项目目录。
- 安装依赖后可以直接启动。
- 执行启动命令后，能够同时启动前端和本地 WebSocket 服务，并在浏览器中打开系统。
- 启动方式、项目结构、端口和基本使用说明写入 README。
- 使用 Node.js 18+，前端框架不限，但必须可以本地运行。

2. 基础白板功能
- 支持自由画笔、直线、矩形、椭圆、文本、便签和橡皮擦。
- 支持选择、移动、缩放、旋转、删除和复制元素。
- 支持图层顺序调整，至少包括置顶、置底、上移一层、下移一层。
- 支持画布缩放和平移，并提供复位视图功能。
- 支持不同颜色、线宽、填充样式和字体大小。
- 每个用户有独立的撤销和重做栈，撤销不能影响其他用户的修改。

3. 实时协作同步
- 多个浏览器窗口可以通过房间号加入同一个白板。
- 服务端使用 WebSocket 广播操作，客户端实时更新。
- 显示在线用户列表、用户颜色、用户名称和远程光标位置。
- 显示当前连接状态：已连接、重连中、离线。
- 新用户加入时必须先拉取当前完整快照，再接收增量操作。

4. 离线编辑与重连合并
- 断网时用户仍然可以继续绘画和修改，操作先写入 IndexedDB 离线队列。
- 网络恢复后自动重放离线操作，并显示同步进度。
- 使用版本号、向量时钟或等价机制判断并发冲突，不能简单用“最后写入覆盖”处理。
- 对同一元素的并发移动、并发删除和并发属性修改要有确定性的合并规则。
- 冲突时不能静默丢失用户操作，必须在界面上显示冲突记录或合并结果。
- 刷新页面后，未同步的离线操作不能丢失。

5. 服务端持久化与恢复
- 服务端将房间快照和操作日志持久化到本地 SQLite 或 JSON 文件。
- 服务端重启后能够恢复已有房间内容。
- 支持导出当前白板为 JSON 和 SVG。
- 支持导入之前导出的 JSON，并重建画布。
- 支持清空当前房间，但必须二次确认，并记录清空操作。

6. 状态与冲突面板
- 提供一个状态面板，展示在线用户、待同步操作数、最近同步时间、重连次数。
- 提供一个冲突记录面板，列出发生冲突的元素、参与用户、冲突类型和最终合并结果。
- 支持点击冲突记录后高亮对应元素。
- 断网、重连、合并、失败时都要有明确的状态提示，不能只显示一个转圈图标。

7. 页面和操作
- 至少包含：开始页、创建/加入房间页、白板主页面、帮助页和冲突记录页。
- 主页面包含工具栏、画布、用户列表、状态面板和缩略图。
- 支持键盘快捷键，例如撤销、重做、删除、复制、粘贴。
- 所有按钮都必须真实可用，不能有占位按钮。
- 页面适配常见电脑屏幕尺寸。

8. 测试和完成标准
- 为 CRDT 或等价合并逻辑、离线队列、撤销重做、冲突判断、快照序列化和存储恢复编写基本测试。
- 完成后实际运行测试。
- 在浏览器中至少用两个窗口完成一次实时协作、一次离线编辑、一次重连合并和一次服务端重启恢复。
- 不要留下空函数、假数据、无效按钮或明显 TODO。
- 最后说明修改和新增了哪些文件，以及如何启动项目。

9. 展示与录屏验收
- 启动服务后打开两个浏览器窗口，加入同一个房间。
- 在 A 窗口绘制图形和文字，B 窗口实时显示；在 B 窗口选择并移动元素，A 窗口同步更新。
- 展示在线用户列表和远程光标。
- 让 B 窗口断网，在离线状态下连续绘制和修改元素。
- 恢复 B 窗口网络，展示离线操作自动重放、同步进度和合并结果。
- 制造一次同一元素的并发修改，展示冲突记录面板、冲突说明和最终结果。
- 演示每个用户独立撤销重做，确认不会影响另一个用户。
- 导出 SVG 和 JSON，再导入 JSON 恢复画布。
- 重启本地服务，刷新页面，确认房间内容能够恢复。
- 录屏要求：从干净状态启动，完整展示真实输出，失败过程不要剪掉，时长控制在 90 秒以内。
