【缺陷报告】miniregex：非捕获组被算进了分组编号

仓库里的 miniregex（自研迷你正则引擎）有一条测试挂了：

    FAIL: test_group_numbering (test_miniregex.TestAlternationAndGroups.test_group_numbering)

    FAILED (failures=1)

复现：

    python3 -m unittest test_miniregex -v
    # 61 条里只挂这一条，其余全绿

影响面比一条用例大：模式里只要出现非捕获组 `(?:...)`，它后面的捕获组编号就整体后移——`(a)(?:b)(c)` 这种模式的分组个数、`groups()` 返回的元组、以及 `\1`…`\9` 反向引用的解析与校验都会跟着错。也就是说表面只挂一条，实际是编号语义错了。

你要做的：

1. 修掉根因，让 61 条测试全绿；不许改测试。
2. 语义要求（README 里要写清）：捕获组按左括号出现顺序从 1 开始编号，非捕获组 `(?:...)` 不占用编号；`\n` 引用第 n 个捕获组，引用不存在的组抛 `PatternError` 且 `position` 指向反斜杠；`groups()` 只包含捕获组，未参与匹配的组用 `None` 占位；`start(i)`/`end(i)` 对未参与的组返回 -1。
3. 回归验证：补一组混合写法的测试，至少覆盖 `(a)(?:b)(c)`、`(?:(a))(b)`、`(?:a)(b)(?:c)(d)`、`(a)(?:b)\1`、以及越界引用 `(a)\2`。
4. 其余行为不许回退：贪婪与懒惰、选择分支的 leftmost 语义、锚点、字符类、以及 ReDoS 步数上限（`(a*)*b` 这类仍要抛 `MatchLimitError`）都保持现状。
5. 对照 README 的语法表，确认「非捕获组不参与编号」这条已经写明，没写就补上。

提示：解析器里处理 `(` 的那段代码是入口，注意「是不是捕获组」和「占不占用编号」是两件事。
